### Added
- **Fleet lane telemetry in the live display (fleet track, design §4.3)**: the gateway and fleet clients now emit `on_lane_update` around **real network calls only** (replay runs show no lanes — lanes are never theater). One lane per model under the active stage's footer — `└ qwen35-397b-a17b   extractor · 1 in-flight · 1 call · RPM 3/15` — with the RPM coming from the RateBroker's new trailing-60s `usage_snapshot()` (an active 429 penalty renders as a warn `429 cool-down Ns`). Up to 4 lanes visible, beyond that one `+N more · M in-flight` aggregate (footer stays ≤8 lines); lanes clear on stage transitions (the permanent ✓ line carries totals). Today's default run shows the single extractor lane — completing the T5 "single-lane RPM display"; judge/reranker/embeddings lanes appear automatically once their flags flip post-PC-2 (sinks now ride into those clients from `run.py`). Producer hooks are never load-bearing: broker oddities degrade to zeroed usage instead of raising.

- **`REDESIGN_PLAN.md` committed + reconciled (fleet track start)**: the multi-agent redesign plan was referenced by `ARCHITECTURE.md` and `TERMINAL_DESIGN.md` but only existed as an untracked local file still claiming "no code written". Now committed (v0.2) with a verified status table: **PR1–PR11 + the `hierarchical/` cleanup all shipped**; open items are PR12a embedding threading, the `EWSConfig.folders` remainder of PR12b, the §4.3 fleet lane display, and the corp preconditions PC-1/PC-2 that gate flipping the fleet live-flags. One recorded deviation: `assemble/jsonout.py` was kept (not deleted) and now carries the U4 reader fields.

- **LLM failure explainer (owner comment, U7)**: when something goes wrong but the LLM endpoint works — **`actionpulse explain [--trace-id|--date]`** collects the run's own telemetry (whitelisted `trace-*.meta.json` fields: status/error/`stage_health`/durations/LLM trace/budget — never `config_sanitized`, never email bodies; plus the tail of the already-redacted structured log) and makes **one** compact JSON-mode call (`prompts/explain_failure.v1.txt`, domain facts baked in: corp-only endpoints, 401/403=token rotation, 429/5xx=transient, "skipped"=idempotency) → a short *likely cause / explanation / next steps* card; answers follow `report.language`. Rides the existing `LLMGateway` on its **own** `explain` stage budget — it never competes with the pipeline's 2 calls (ADR-008) and inherits retries/429 penalties/auth classification. The menu offers "Ask the LLM what went wrong?" after a crashed run (Esc declines); a failed `actionpulse run` prints the hint. Offline it fails fast with the corp-network message (ADR-012). **Agent-CLI-under-the-hood analyzed and rejected** (would hand `LLM_TOKEN` to a third-party binary for a single deterministic collect→ask→print step; recorded in roadmap U7), and **"chat with your inbox" deferred with reasons** (U8: honest answers need query-relevance retrieval — the fleet's embeddings/reranker work — today's SELECT ranks by digest priority, not the question). Corp validation: runbook §9.4 gains the C5 protocol.

- **Maintenance: cleanup + logging toggle (owner comment, U6)**: new menu item **Maintenance — disk usage · cleanup · logging** shows what occupies the data home (digests / logs / state, plus the legacy `~/.digest-logs` and `/tmp/digest-logs` when present) and offers: clean logs (incl. legacy dirs) · clean digests older than 14 days · clean ALL digests+logs (confirmed; **state, config and secrets are never auto-cleaned** — deleting the EWS watermark would change fetch behavior) · **file-logging toggle** (new `observability.log_to_file`, default **on**; rewrites `configs/config.yaml`; an explicit `--log-file` still wins). Scriptable twin: **`actionpulse clean`** (no flags = usage read-out only; `--logs/--digests/--all`, `--older-than N`). Telemetry honesty instead of a fake kill switch: nothing phones home — logs and Prometheus/healthz ports are local, OTel tracing is off by default — and the screen says exactly that.

- **One data home — runtime files stop scattering (owner comment, U5)**: digests/trace-meta used to land in **cwd-relative `./out`**, logs in `~/.digest-logs`, and the EWS sync watermark in **cwd-relative `.state/`** — that last one was a real bug (the incremental window silently reset whenever you ran from a different directory). Everything regenerable now lives under **`<data home>/var/{out,logs,state}`**, where the data home is `$ACTIONPULSE_HOME` → the install checkout (`~/ActionPulse`) → `~/.local/share/actionpulse` (wheel installs never write into site-packages). Explicit `--out`/`--state`/config values always win. New **`actionpulse paths`** command + the menu config view print the full map. Deliberate, documented exceptions: secrets stay in `~/.config/actionpulse/env` (inside the checkout `git clean -xdf` would delete them and `git add -f` could leak them; systemd wants a re-clone-stable path), CA chain in `~/.ssl`, launcher on PATH. `last_run.json` moved into `var/state` (the old location is still read). `configs/config.example.yaml` no longer pins `sync_state_path` (re-running `actionpulse setup` migrates existing configs); the config-default change alters `config_sha256`, so the first run after upgrade rebuilds once (expected).

- **Interactive digest reader (owner UX comment 4b, U4)**: `actionpulse read [--date YYYY-MM-DD] [--out DIR]` + a "Read digest" menu item + a post-run "Read the digest now?" offer. Line-oriented drill-down on the §5.2 selector — digest (newest first) → section → item → a **detail card printed into scrollback** with the topic (`email_subject`), the author (`email_from`), the distilled action, due/confidence, honesty badges (`⚠ weak`, `seen before`), the verbatim source-language quote(s), and the `evidence_id` + `msg_id` trace (P2). Esc walks back up one level; long lists page at 6 + nav rows so the 1–9 quick-select invariant holds; non-TTY `read` prints the markdown digest (scriptable). **Design §5.1 reaffirmed** after a three-way posture comparison (drill-down vs `$PAGER` vs bounded alt-screen) — scrollback-as-evidence won; recorded in `TERMINAL_DESIGN.md` §5.1/§9. **Data side**: items in the JSON artifact now carry `email_subject` and the new `email_from`, populated at assemble time from the normalized message behind each item's `msg_id` — the artifact is self-contained (no ingest-snapshot join; older artifacts load fine, system banners skipped, existing values never overwritten). `PIPELINE_VERSION` 1.1.0 → 1.2.0 so the next run rebuilds existing artifacts with the new fields (one-time; subjects/authors are report-class data — on disk and screen, never in logs). New `reader-card.svg` README screenshot rendered by the real card builder; reader pty round-trip + enrichment e2e tests; `test_reader.py` added to the `terminal-matrix` CI job.

- **Run options in the launcher menu (owner UX comment 4a, U3)**: "Run digest" now asks exactly one follow-up — a §5.2 selector for the daily decision: **Today (calendar day)** (default, Enter-through) · **Today (rolling 24h)** · **Yesterday** (absolute date shown) · **Pick a date…** (validated `YYYY-MM-DD`; empty input backs out) · **Re-run today (`--force`)** (bypasses the idempotency skip) · **Repeat last run** (offered only when a previous choice exists; the label always shows the stored absolute params — no silent drift) · **Back**. Esc backs out to the main menu and never runs anything (`cancel_value`); a run that crashes does not persist its params. The accepted choice is saved to `~/.config/actionpulse/last_run.json` (no secrets; loaded defensively). `out/state/model` stay config/CLI concerns by design — the menu is for the daily decision, not plumbing. New **real-pty round-trip tests** (`tests/test_menu_pty.py`, first in the repo: arrows/quick-select/lone-Esc/SIGINT→130 against a spawned tty) added to the `terminal-matrix` CI job; new `run-options.svg` README screenshot.

- **Intra-stage liveness + retry/error counters (owner UX comments 1+2, U2)**: the run display now updates *inside* long stages, not just at their boundaries. Two new `ProgressSink` events — `on_stage_progress` (EWS paging: `247 messages · page 3`; normalize and evidence split: `n/total`) and `on_stage_retry` (EWS reconnects via tenacity `before_sleep`, LLM 429/5xx transient retries, the LLM quality retry now shows as `attempt 2/2`). The live footer renders running counters at 10 fps and **warms to amber immediately on a pending retry** (a silent 60 s backoff is now legible); `PlainSink` prints every retry (rare, honest) and collapses data progress into a ≥10 s "still running" reassurance line (terraform model), so CI logs stay quiet. Permanent ✓/✗ lines gain a warn suffix **only when nonzero** — `✓ INGEST  247 messages · ↻2 retries (31.2s)` — and the same numbers land in `trace-*.meta.json` as `stage_health` (plus `pages`/`retries`/`skipped` in `ews_fetch_stats`) for the corp runbook read-out. Producers emit through the swallow-and-log `progress.emit()` helper, so a broken renderer still cannot break the pipeline. Design doc §4.2/§4.4 amended; THREADS/SELECT deliberately stay silent (sub-second; cargo's no-bar-under-500 ms rule).

**Clarification (documentation, 2026-04):** The **default daily CLI** (`python -m digest_core.cli run`) assembles a `Digest` with `schema_version="1.0"` and extraction prompts `extract_actions*.v1`. The **`EnhancedDigestV3` / `mvp.5`** pair applies to the LLM gateway’s **separate** summarization path (`process_digest` with Jinja `summarize/mvp/v5`), not to that default run output. Package-level constants in `digest_core/__init__.py` describe the V3/mvp.5 contract for that gateway path; avoid assuming they describe the JSON shape written by `run` without checking `run.py` and `llm/schemas.py`.
